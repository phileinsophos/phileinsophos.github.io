Namespace-based UUIDs (UUIDv3 and UUIDv5) generate unique identifiers based on a name and a namespace, using a hash function. Both UUIDv3 and UUIDv5 follow the same steps, with the only difference being the hashing algorithm used:

  • UUIDv3 → uses MD5
  • UUIDv5 → uses SHA-1

Why Use Namespace-based UUIDs?

  • Deterministic: The same namespace + name will always produce the same UUID.
  • Useful for Identifying the Same Entity Across Systems.
  • Great for deduplication, caching keys, and consistent references.

How Namespace-based UUID Generation Works (v3 & v5)

Step 1: Choose a Namespace

A namespace is a predefined UUID that represents a category. You can use standard ones defined in RFC 4122:

Step 2: Provide a Name (String Input)

This is the unique name within the namespace.
Example: “example.com” or “user-123”

Uniqueness comes from the combination of namespace + name. As long as your namespace choice is consistent, and the name is unique within that context, you’re good.

Step 3: Convert to Bytes

  • Convert the namespace UUID to 16 bytes.
  • Convert the name string to UTF-8 encoded bytes.

Step 4: Concatenate

Join the namespace bytes + name bytes into one byte stream. When the namespace (16 bytes) and name (can be many bytes) is concatenated, it becomes bigger than 128 bits. But it’s okay, because its hashed and then only the first 128 bits of the has are taken.

Step 5: Hash the Combined Bytes

  • v3: Use MD5 (128-bit output)
  • v5: Use SHA-1 (160-bit output → only first 128 bits used)

Structure into UUID Format

Break the 16 bytes into standard UUID string format:

xxxxxxxx-xxxx-Mxxx-Nxxx-xxxxxxxxxxxx

Where:

  • M = version number (3 or 5)
  • N = variant (most commonly 8, 9, a, or b)

How to Identify if a UUID is v3 or v5?

Each UUID stores its version in a specific field inside it. The version number (1, 3, 4, 5, etc.) is stored in the 13th hex character of the UUID string. (Or more precisely, in the 4 most significant bits of the “time_high_and_version” field.)

Suppose you have these UUIDs:

f47ac10b-58cc-**3**837–8f07–9141eabff989
  • 13th character is 3. It is a UUIDv3 (Name-based, uses MD5 hashing).
c9bf9e57–1685-**5**d21–8c36–47865a1c0c57
  • 13th character is 5. It is a UUIDv5 (Name-based, uses SHA-1 hashing).
